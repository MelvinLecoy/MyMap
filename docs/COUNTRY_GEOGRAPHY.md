# Authoritative country and city geography

The owner's `countries_categorization.xlsx` replaces the earlier travel classification for both countries and their cities. Its literal Continent / Region / Subregion values are the authority, including deliberate empty cells. This classification is reference data, not an editable travel preference.

The complete original is archived at [countries_categorization.xlsx](../data/sources/country-geography/countries_categorization.xlsx). [Provenance](../data/sources/country-geography.json) records its SHA-256, sheet, row count and extracted CSV hash. The workbook contains one `Countries` sheet with 197 country rows; every code and name matches the existing 197-country overview. The document is read as tabular data only.

[country-geography.csv](../data/reference/country-geography.csv) stores `CountryCode,Country,Continent,Region,Subregion`. Country codes join identities; labels are not guessed from city names or third-party geography. Custom labels such as `British Isles`, `Powerhouse`, `Jihadist 4`, `Dacia 3`, `Mekong 5` and `Maritime 6` are copied verbatim. All 12 South American countries intentionally have no Region or Subregion. Blank levels stay blank, and profiles omit their separators.

Svalbard (`SJ`) is absent from the workbook. Its country keeps its existing Europe continent with no inferred Region/Subregion. Its city retains its existing Europe / Nordic geography. No territory classification is borrowed from a metric source or a sovereign country.

Run `npm run country:prepare-geography` to reproduce the CSV and provenance ; city rows inherit geography by CountryCode and store none of those copied fields. `npm run country:verify-geography` checks the extraction and city CountryCode references without writing files. These commands use Python's standard library.

`scripts/country-geography-importer.ts` validates unique known codes, exact country names, complete country coverage, recognized continents, all five headers and parent regions for subregions. Production data import passes this reference into `importCities`, writes `src/generated/country-geography.json`, and produces city geography from the same authority. A production city must have an explicit classified CountryCode; `SJ` is the explicit unchanged exception. Demo and isolated importer fixtures can retain their independent data contract when they do not opt into the reference.

At runtime, `App.tsx` applies `applyCityGeography` and `applyCountryGeography` from `src/lib/country-geography.ts` after selecting the latest database or bundled personal records. A stale database snapshot therefore cannot restore an obsolete classification for a covered country. Runtime city records with a null or newly unlisted country code preserve all their existing geography and remain usable until their reference metadata is reviewed; the helper does not guess a country or throw during rendering. Import validation explicitly opts into `{ strict: true }` to require coverage, while `SJ` remains unchanged in both modes. These pure helpers replace geography only: personal statuses, dates, actual stays, durations, map URLs, coordinates and notes remain intact. Country profiles use the same slash-separated hierarchy as city profiles.

This travel hierarchy is independent of reference metrics and their comparison pools. The earlier metric workbook, raw figures, indices, saved medians and `country-comparison-regions.csv` are unchanged. In particular, Turkey's stored metric grouping and its Europe comparison override retain their existing meanings; the new travel classification does not recalculate a median.

When adding countries, territories or cities later, keep identity and ownership relationships separate from this hierarchy. Add explicit owner-approved classifications to the reference source rather than inferring a territory's travel hierarchy. Validate the CSV and database geography synchronization before release. Future favourites, planning states, visa records and map actions belong to mutable records and must not overwrite this reference.
